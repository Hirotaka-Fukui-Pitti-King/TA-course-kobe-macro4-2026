はじめに

TAセッション3の目的

第1回と第2回のTAセッションではJuliaとQuartoを用いてレポート課題を作成する方法についてみていきましたが、今回はGithubを使って課題を提出する方法についてみていきます。

セットアップ

VS CodeでGitをセットアップします。最初にWindowsへGitをインストールし、VS CodeからそのGitを利用します。流れとしては

Gitをインストール
        ↓
VS CodeからGitを確認
        ↓
名前・メールアドレスを設定

になります。

GitをWindowsにインストールする

公式のGit for Windowsからインストーラーを取得できます。インストール後はVS Codeをいったん終了して再起動してください。

VS Codeを開き、Terminal → New Terminal を選択します。WindowsであればPowerShellが表示されます。次のように入力します。

git --version

バージョンが表示されれば成功です。

Gitに自分の名前とメールアドレスを登録する

VS Codeのターミナルで次を実行します。

git config --global user.name "Your Name"

続いてメールアドレスを設定します。

git config --global user.email "your@email.me"

これはGitHubへのログイン情報ではありません。コミットのAuthorがだれなのかという情報です。設定を確認するには、

git config --global user.name
git config --global user.email

GitHubと接続する

Ctrl + Shift + Pでコマンドパレットを開きます。そして、Publish to GitHub を探します。初回であれば、Sign in to GitHub というログイン画面が表示されるのでログインし、VS Codeとの接続を許可します。

Github入門

卒論などを作成した際、次のようなファイルを作ったことはないでしょうか。

  • 卒論.docx
  • 卒論_修正版.docx
  • 卒論_最終版.docx
  • 卒論_最終版2.docx
  • 卒論_本当の最終版.docx

どれが最新？

このような管理方法には問題があります。どのファイルが最新なのかわからなくなるだけでなく、いつ、何を、なぜ変更したのかも記録されません。複数人で作業する場合、さらに複雑になります。

GitとGithubはこの問題を解決するためのバージョン管理システムです。Gitでは一つのファイルを何度もコピーする代わりにプロジェクトの変更履歴を記録します。変更前と変更後を比較したり、過去の状態を復元したりできます。

基礎概念

レポジトリ

レポジトリ（Repository）はファイルとその変更履歴を管理する場所です。例えば、レポートでデータ分析のコードとレポート本文を作成するとします。通常のフォルダでは現在のファイルを保存しますが、レポジトリではそれらのファイルが過去にどのように変更されたのかも記録できます。

この履歴があれば最新のコードだけでなく、以前の推定方法や、どのコミットで分析内容が変更されたのかも確認できます。ここで重要なのは、Gitは単にファイルを保存するのではなく、コミットによってプロジェクトの状態を記録するということです。

コミット

コミット（Commit）はプロジェクトのある時点の状態を変更履歴として記録する操作です。例えばレポートを作成しているとします。最初にデータを読み込むコードを書き、そのあと回帰分析を追加し、最後に標準誤差の計算方法を変更したとしましょう。Githubではこうした作業の節目ごとにコミットを作成できます。

Local RepositoryとRemote Repository

Gitでは主に2種類のリポジトリを区別します。

Local Repository（ローカルリポジトリ）

自分のパソコンの中にあるGitリポジトリです。その中の .git ディレクトリにコミット履歴などが保存されています。ローカルリポジトリで

git status
git add Report.qmd
git commit -m "Add Report.qmd"
git log

という操作ができます。

Remote Repository（リモートリポジトリ）

ネットワーク上にあるGitリポジトリです。代表的なものがGitHubです。ローカルで作成したコミットをGitHubへ送るには、

git push

を使います。逆にGitHub上の変更を自分のパソコンへ取り込むには、

git pull

を使います。したがって、全体像は次のようになります。

自分のパソコン: Local Repository
       │
       │ git push
       ▼
GitHub: Remote Repository
       │
       │ git pull
       ▼
自分のパソコン: Local Repository

基本操作: Push と Pull

GitでLocal RepositoryとRemote Repositoryを使うとき、中心となる操作が push と pull です。Pushは自分のコミットをRemote Repositoryへ送る操作、PullはRemote Repositoryの変更を自分のLocal Repositoryへ取り込む操作です。

例えば、自分のパソコンで Report.qmd を修正し、

git add Report.qmd
git commit -m "Add Report.qmd"

と操作します。コミットした時点では変更履歴はまだ自分のLocal Repositoryにしかありません。ここで、

git push

を実行するとローカルで作成したコミットがGitHubのRemote Repositoryへ送信されます。

Local Repository
       │
       │ git push
       ▼
GitHub: Remote Repository

今度は、他の人がGitHub上のリポジトリを更新したとします。例えば先生が課題をGitHubのRemote Repositoryへ追加したとします。そこで、

git pull

を実行します。するとRemote Repositoryにある新しいコミットを取得し、自分の現在のブランチへ統合します。

Remote Repository
       │
       │ git pull
       ▼
Local Repository

つまり、Pushは「自分から共有場所へ送る」、Pullは「共有場所から自分へ取り込む」操作です。

課題の提出方法

課題提出用レポジトリを自分のPCに保存する

macro4-Your-Nameという形で課題提出用のプライベートレポジトリが作成されているはずです。これを自分のパソコンで触れるように設定します。

Ctrl + Shift + Pを押し、コマンドパレットを開きます。Git: Cloneを探して選択します。

GitHubにサインインしている場合は Clone from GitHubという選択肢が出てくるはずなのでそれを押し、macro4-から始まる自分のレポジトリを探して選択します。

PC上での保存場所を選び保存します。

GitHub による提出

課題ごとにフォルダ (00/, 01/, ...) が作られます。その中の answer.qmd に解答やコードを書き、push することで提出することができます。新しい課題のフォルダは課題が発表されるタイミングで先生からそれぞれのレポジトリに push されるのでgit pull してから作業を行ってください。

提出に必要なファイルは answer.qmd と, パッケージを追加したときの Project.toml の2つだけなので、それ以外のファイルは変更しないようにしてください。

提出練習

00というフォルダがあるはずなのでそれを用いて提出の練習をしてみましょう。00の中にはanswer.qmd と Project.tomlがあるはずです。

空白になっているところがあるのでそこに文章やJuliaのコードを適当に何か書いてみましょう。

cd 00
julia --project=. -e 'using Pkg; Pkg.instantiate()'   # 初回だけ
quarto render answer.qmd

その後、pushして提出します。しばらくするとsubmission-00というブランチにanswer.pdfが作られるはずなのできちんとrenderされたかどうか確かめてみましょう。
